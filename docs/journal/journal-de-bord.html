Pourquoi cet ordre. On construit d'abord la tuyauterie (événements, horloge, appels LLM) avec très peu d'agents, pour vérifier que tout circule. Le rejeu arrive tôt (étape 8) parce qu'il permet ensuite de développer la scène 3D sur des runs enregistrés, sans occuper la carte graphique avec les modèles. Le contenu du monde (marque, corpus, population complète) vient une fois la chaîne fiable.

Étape 0 — Nettoyage du dépôt

16 octobre 2026 · Exigences concernées : aucune directement ; prépare toutes les suivantes.

Objectif

Repartir d'une base propre : ne garder dans le dépôt que ce qui est conforme aux règles du projet (CLAUDE.md), aux décisions de conception (docs/contexte-projet.md) et à l'énoncé.

Pourquoi on a repris de zéro

Un premier prototype avait été écrit avant que la conception soit arrêtée. En le comparant aux règles du projet, plusieurs écarts sont apparus, dont certains touchent des exigences notées :

Écart dans le prototypeRègle ou exigence concernée
Nom de marque, ingrédient et indice de protection écrits en dur dans le code et les promptsLe nom doit rester un paramètre de configuration, choisi après un test de contamination
Topics simulation.* au lieu des 7 topics sim.* prévusC1, architecture
Événements sans run_id, sans caused_by, et date de traitement en temps réel au lieu du temps simuléC3 (deux horloges), F6 (traçabilité), E3 (rejeu)
Pas de Redis ; images Docker en version latestF3 ; livrable reproductible sur une autre machine
Pas de .gitignore, fichiers compilés Python versionnés, arborescence différenteConventions du dépôt
Visualisation 2D à base d'icônesRemplacée par une scène 3D (décision du binôme)

Corriger ces écarts un par un aurait coûté plus cher que de reconstruire proprement, étape par étape.

Ce qui a été fait

  • Retrait du prototype du dépôt : src/, godot_client/, docker-compose.yml, requirements.txt. Ces fichiers avaient été commités, ils restent donc consultables dans l'historique git (commit 607297b).
  • Archivage hors du dépôt des fichiers jamais commités, qu'une suppression aurait perdus définitivement : src/agents/, src/rag/, src/simulation_engine.py, data/knowledge/, les caches Godot et l'environnement virtuel. Ils sont dans C:\Users\Siradiou\archive_prototype_S9_2026-10-16\.
  • Mise à jour de CLAUDE.md : chemin correct de l'énoncé, Python 3.12, Godot en 3D low-poly, et une section « Méthode de travail » qui fixe la règle d'avancement étape par étape.
  • Journal des décisions complété dans docs/contexte-projet.md.
  • Création du README.md : description du projet pour GitHub et tableau d'avancement, mis à jour à chaque commit.
  • Installation de Python 3.12.10 avec le gestionnaire d'installation officiel (py install 3.12), pour l'utilisateur seulement, sans droits administrateur. Python 3.14 reste installé et reste la version par défaut ; on appelle 3.12 explicitement avec py -V:3.12.
  • Création de ce journal de bord : source HTML dans docs/journal/journal-de-bord.html, PDF généré à la racine par docs/journal/build.ps1 (impression via Microsoft Edge, déjà présent sous Windows, donc aucune dépendance à installer).

À retenir pour l'oral

  • Le projet a été reconstruit sur une conception écrite et validée avant de coder, pour que chaque composant réponde à une exigence identifiée de l'énoncé.
  • Interpréteur et environnement virtuel sont deux choses distinctes : Python 3.12 est installé une fois sur la machine, puis l'environnement virtuel .venv du projet (étape 1) est créé à partir de lui et contient toutes les bibliothèques. Ainsi les dépendances du projet n'interfèrent pas avec le reste de la machine, et la procédure se reproduit sur la machine de la collaboratrice.
  • Rien n'a été perdu : l'ancien code est dans l'historique git ou archivé.
